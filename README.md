# 便利店临时闭店调度系统（演示）

设备停电、道路封控或员工缺勤时，门店申请临时闭店；区域经理确认后门店停止接新单，
未取自提订单进入**跨店改派 / 退款**队列。纯 Python 标准库实现（`http.server` + SQLite），
配送与支付由模拟适配器返回。

## 一条命令启动（自带停电案例）

```bash
./run.sh
```

打开 http://127.0.0.1:8000 。脚本会重置 `data/store.db` 并播种演示场景：

- **望江路店（ST-A）** 冷藏柜停电已 35 分钟，店员王芳发起闭店申请，待区域经理审批；
- 4 个未取订单覆盖全部处置分支：

| 订单 | 状态 | 含冷藏 | 预期处置 |
|---|---|---|---|
| O-1001 | 已备货 | 是（已超 30 分钟安全时长） | 仅可退款（橙色紧急） |
| O-1002 | 已通知顾客 | 是（超时） | 仅可退款 |
| O-1003 | 骑手正在路上 | 否 | 先召回骑手，可改派/退款 |
| O-1004 | 已备货 | 否 | 可改派至河滨花园店 |

- **河滨花园店（ST-B）** 库存充足可承接；**城南银泰店（ST-C）** 牛奶缺货、乌龙茶仅 1 瓶，
  改派候选实时校验库存（跨店不足时只能退款）。

## 主要业务规则

- **审批权限**：店员只能为本店发起申请；审批必须由区域经理完成，且**任何人不能审批自己发起的申请**。
- **改派/退款互斥**：`order_outcomes.order_id` 唯一约束 + 触发器保证并发下订单只进入一个结果，
  后到的操作返回 409 `order_settled`。
- **冷藏时限**：停电超过 `CHILLED_SAFE_MINUTES`（默认 30 分钟）的冷藏订单强制进入退款队列，禁止改派。
- **库存占用**：改派先在目标店生成 `held` 预占（TTL 15 分钟），确认后 `committed`；
  顾客拒绝、超时或门店提前恢复时自动释放。
- **全程留痕**：申请、审批/驳回、撤销、延长、提前恢复、顾客拒绝改派均写通知日志（只追加）与闭店时间线。

## 常用操作（看板按钮）

经理确认闭店 → 每单选择「跨店改派」（下拉只展示库存充足门店）或「退款」；
也可模拟「顾客拒绝改派」、「延长预计恢复」、「恢复开店」（提前恢复释放预占并通知顾客）。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖：改派/退款并发排他、冷藏安全时限、跨店库存预占与释放、审批权限（自审/店员审批被拒）。

## 目录

```
app/
  config.py            路径与业务参数
  db.py                SQLite schema（含互斥触发器、部分唯一索引）
  adapters.py          模拟配送 / 支付适配器
  services/
    closure.py         闭店申请、审批、撤销、延长、恢复
    orders.py          受影响订单、库存预占、改派、退款、看板聚合
    notify.py          通知日志
  web/                 HTTP API + 看板页面（白/深灰/橙，移动端固定按钮）
  seed.py              停电案例种子数据
data/                  SQLite 库 + 本地演示订单附件（运行时生成）
tests/                 unittest 用例
```
